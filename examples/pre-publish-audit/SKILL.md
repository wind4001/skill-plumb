# 提交前自查

先运行确定性本地脚本（零依赖，内置正则与结构化链接解析双谓词、实测 `git add -n` 而非 `git check-ignore`）：

```bash
node <skill_dir>/scripts/audit_all.mjs <repo_dir> [--pii "敏感值1,敏感值2"] [--out report.json]
```

> 单项复验可直跑 `audit_secrets.mjs`（§1/§1b/§3/§10）、`audit_paths_ports.mjs`（§2/§4/§5/§6/§9）或 `check_links.mjs`（§7）。用户提供手机号/商户名/账号等隐私值时务必传 `--pii`（或 `PRE_PUBLISH_PII`），以穷举长度 ≥4 子串并同时覆核本次新写的测试文件。

## 退出码与覆盖纪律

- `0`：全量机检完成（**不等于干净**，必须读 `summary` 与 `calibration`，确认 `files_scanned > 0`）。
- `1`：CLI 参数无效、目录不存在或脚本异常。
- `2`：覆盖不全（非 git、`--no-history`、不可读文件/目录、大文件、越界符号链接）——**严禁宣称“全部干净”**，所有 `scopes_skipped` 与 `skipped` 必须写入「未验范围」。

## 人工核查与高危红线

1. **绝不回显原始凭据/PII**：报告仅给位置与脱敏摘要；历史中出现真凭据时，清工作区不够，**必须提醒轮换**。
2. **修完即复验**：硬编码路径、签名 URL（下载到本地 `docs/assets/` 并按文档自身目录写相对路径）、失效链接修改后，必须重跑脚本复验。
3. **数据库口令与端口**：Compose 本机服务应绑 `127.0.0.1`；**`POSTGRES_PASSWORD` 仅在空卷生效**，已有数据卷勿直接改默认值（改文档提醒或 `ALTER USER`/重建卷）。
4. **文档一致性与无上下文复核**：结合 `doc_drift_hints.changed_files` 核对代码与文档说法（改完正文别漏折叠区/子文档）；若本次改了 README 或将公开仓库，派无上下文 subagent 按章节标题分轴核验「读者能否照做」与「文档与代码是否一致」。
5. **发新公开仓库换历史不换 remote**：优先 `git checkout --orphan` 重建干净历史；若重写历史，**必须同时断言 commit hash 已变（防静默空跑）且 tree hash 未变（防伤代码）**，清理 `refs/original` + `reflog`/`gc` 后用 `--pii` 重跑复验。

## 输出格式

输出 Markdown 核查表（`检查项 | 结果 ✅/⚠️/❌ | 证据 文件:行号`），并把所有发现严格分成三桶：
- **可直接修并复验**（硬编码路径、断链/绝对链接、签名 URL 替换）
- **需用户决策**（凭据轮换、删除跟踪的隐私文件、端口/默认口令、作者/提交者邮箱覆盖或重写历史、补 LICENSE）
- **未验范围**（脚本 `scopes_skipped`/`skipped`、未传 `--pii`、未执行的语义/读者复核项）

## 必须拒绝的偷懒借口

- ❌ 看到 `Exit 0` 或机检零命中就跳过 §6 文档与代码语义核对，或漏扫本次新写的测试文件；
- ❌ 把 `Exit 2`（非 git、`--no-history`、不可读/超大文件、越界软链）简化为「已查干净」；
- ❌ 发现凭据或 PII 后把原始字面量贴进聊天/报告，或只删工作区文件却不提醒轮换与清历史。
